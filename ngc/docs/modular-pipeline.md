# 模块化模型、数据与实验管线

状态：总体设计，2026-09-11。registry、资产哈希检查、静态 World/Assembly builder、固定通信步联合仿真协调器和内存 pipeline runner 已有最小实现，详见 [World 使用教程](world.md)。本文还包括未实现的完整目标；`design/f16_hybrid.toml` 仍是不可执行的 F-16 配置草案。

## 1. 两张图，六类可组合对象

不要把气动、数据集、场景和训练器都强制继承一个 Model。它们的生命周期和执行语义不同。

| 对象 | 含义 | 示例 |
|---|---|---|
| Asset | 不可变、有版本的数据与文件 | 气动 HDF5、质量参数、试验轨迹、策略权重 |
| Component | 一段有明确信号契约的计算/动态过程 | 气动函数、发动机、传感器、KF、PID |
| Assembly | 组件、状态与端口的组合 | F-16 飞行器、完整 GNC 闭环 |
| SimulationSpec | 如何推进时间 | 积分器、物理步长、通信步长、执行后端 |
| Scenario / EvaluationSpec | 工况及如何评判 | 初值分布、目标、扰动；指标、失败条件、测试集 |
| PipelineStage | 一项产生实验资产的工作 | 数据准备、配平、训练、评测、报告 |

仿真图描述信号流和状态反馈，可以存在通过状态/延迟闭合的循环。实验管线是有向无环依赖图：准备 → 配平/模型构建 → 训练 → 评测 → 报告。训练 stage 内部可以循环调用仿真，不把在线 PPO 简化成“先收集一个固定数据集再训练”。

## 2. F-16 的组装层次

```text
气动资产 + 插值约定 ──→ 气动组件 ──→ 气动力/力矩
油门 + 飞行条件 ─────→ 发动机组件 ─→ 推力/可选燃油流量
控制指令 ──────────→ 舵机组件 ───→ 实际舵偏
几何/质量/惯量 ─────────────────┐
环境/大气/风 ──→ 空气数据 ────────┤
气动/推进输出 ──→ 力与力矩汇总 ───→ 刚体状态推进
```

气动通常是无状态代数函数；发动机和舵机可能是有状态连续模型；传感器和控制器常为离散模型。数据文件不是每步调用的组件，加载、校验和设备传输在运行前完成。

力与力矩端口除 N/Nm 与坐标系外，还要定义参考点和正方向。升阻力与机体轴三分力不是同一种端口，惯量积也不是只靠矩阵 shape 判断符号。重力的计入位置固定，禁止重复叠加。

## 3. 注册包与人工扩展

建议每个模型包包含：

```text
model_packages/f16_isrl/
  manifest.toml          # ID、版本、来源、依赖、接口版本
  model_card.md         # 方程、假设、包线和已知限制
  components/           # JAX 函数或宿主适配器
  assets/manifest.toml  # 数据、轴、单位、hash、许可与来源
  assemblies/           # 推荐组合
  validation/           # 节点/导数/轨迹参考工况
```

首期以项目目录中的显式 registry 映射 ID 到工厂函数；后续才增加 Python entry points。配置只能引用注册 ID，不运行配置内字符串表达式或任意 Python eval。人为添加一个组件时提供：

1. 稳定的 component ID、实现版本、端口 schema、文档/公式 ID。
2. 类型正确的函数或适配器，以及内部状态/参数定义。
3. 对数据资产的精确依赖及校验值。
4. 至少一个输出参考或数值验证案例。
5. 对后端、批量、梯度、重置和时间调度的能力声明。

参数变化不一定改变实现版本，但展开参数进入实验 hash。算法权重与观测归一化参数一起作为版本资产保存；训练输出不能直接覆盖共享默认参数文件。

## 4. 组件不能一律叫 step

建议分四种语义：

| 类型 | 接口概念 | 谁拥有积分状态 |
|---|---|---|
| algebraic | evaluate(inputs, params) -> outputs | 无内部动态状态 |
| continuous | rhs(t, state, inputs, params) -> derivative；outputs(...) | 原生系统求解器 |
| discrete | update(state, inputs, key) -> state, outputs | 组件状态在采样时刻更新 |
| co_simulation | initialize / advance_to / read_outputs / reset / close | 外部求解器 |

纯 JAX 连续机体、发动机和舵机若强耦合，应拼成联合状态，RK4 每个阶段对联合状态重算相互作用。不能分别调用三个有副作用的 step，再声称得到完整耦合系统四阶积分。

无状态 MATLAB 气动函数可以由宿主在求解阶段求值，但有进程通信开销；有内部积分状态的 MATLAB 发动机必须按通信时间推进一次，不能在 RK4 的假设阶段中反复推进而不回滚。

## 5. JAX 气动 + MATLAB 发动机怎么运行

由 CoSimulationRunner 作为时间协调者，把原生部分编译成一个或多个子系统，MATLAB 发动机作为外部子系统。

一个明确的首版规则是 Jacobi 式固定通信步：在 t_k 同时读取两侧输出，交换后按零阶保持各自推进到 t_(k+1)。原生机体可在一个通信步里执行多个物理子步，但发动机推力在该通信步内保持。

这是一种明确的分区耦合近似。需要通信步收敛试验；即使原生机体内部用 RK4，完整混合系统也不能自动宣称四阶精度。必要时减小通信步，或在具备快照/回滚能力后做迭代耦合。

运行计划要公开能力：

- 全部组件 JAX-compatible 且数据形状固定：候选 `JaxRunner`，再验证 vmap 和可微条件。
- 有 MATLAB/FMU 状态组件：`CoSimulationRunner`；原生分区可 JIT，但整条闭环不默认 GPU 驻留、vmap 或可微。
- 要求端到端梯度但包含无导数适配器：构建时报错，不悄悄返回零梯度。
- 外部实例不支持独立重置/批量：不宣称能直接用于海量并行训练，可用于单实例评测或小规模试验。

外部程序异常、超时与模型数值失效在记录中区分；finally 关闭会话；外部求解器的非精确停止时间必须检查，不能无条件按请求时间记日志。真值权限仍按 NGC 信号边界约束，不因使用外部端口而放宽。

## 6. 资产不是路径字符串

气动数据需要记录：来源仓库和 commit、原始文件 SHA-256、转换器版本、转换产物 hash、轴顺序、轴单位、参考几何、无量纲化、适用域、插值/外推规则。

例如 ISRL 的 F-16 表不仅是 `data.h5`：升降舵网格可能不同，必须按每个系数的数据布局读取；多维 reshape 要验证 MATLAB 的数组顺序。`linear + none` 边界策略属于模型定义，替换为边界外推等同修改模型。

Builder 检查资产与组件 family/interface 是否匹配；同名 F16 并不等于兼容。不同来源组合允许作为新 assembly，但必须标为混合模型并单独验证。

## 7. 场景、训练、评测独立组合

Scenario 定义初值、目标、外部扰动、参数分布和事件；不持有某个求解器实例。EvaluationSpec 定义指标、失败分类、测试工况与统计汇总；不参与训练奖励调参。

Trainer 消费可重置的环境工厂及训练场景，输出 PolicyArtifact。该资产除权重外包含观测/动作 schema、归一化、采样周期、控制层级、训练组件版本与训练分布。

Evaluator 消费冻结策略/控制器、指定模型组合和留出的评测场景，输出 MetricsArtifact 和轨迹。换成 MATLAB 发动机评测时，必须检查策略输入/输出和采样语义；更换模型导致评测结果改变应成为显式实验变量。

Pipeline 示例：

```text
锁定资产 → 校验模型 → 配平工况 ───→ 经典控制器设计 ─┐
                          └──→ JAX 环境中的 PPO 训练 ─┤
独立评测场景 ────────────────────────────────────────→ 评测 → 报告
```

RL Trainer 内部运行 on-policy rollout/update；它不是依赖一个固定预采集数据集。离线学习则使用另一种 stage，明确 train/validation/test 划分。

每次运行输出 resolved manifest：源码版本、资产 hash、展开配置、随机键、执行计划、平台/精度/求解器、外部模型与版本。缓存 key 包含所有影响结果的输入和代码；初期只缓存确定性准备/配平产物，不默认复用有外部隐藏状态的仿真输出。

## 8. Builder 应先做的校验

1. 注册 ID 和版本可解析、资产存在且 hash 匹配、组件实现真实存在。
2. 端口的物理含义、单位、坐标、参考点、形状与 dtype 匹配；转换通过显式 adapter。
3. 每个必需输入恰好有一个来源；多力源通过显式求和组件汇总。
4. 采样周期、通信步长和时间戳约定一致；每个状态有唯一积分所有者。
5. 检出当前不支持的直接馈通代数环。含状态/延迟的反馈不是普通 DAG 错误。
6. 后端、梯度和批量要求满足；不满足时拒绝或由用户选另一份明确配置。
7. Pipeline 产物依赖无环、策略 schema 与评测接口兼容。

## 9. 对现有骨架的最小扩展

新增 `catalog/`（ID 与资产元数据）、`composition/`（组件契约、装配与校验）、`pipelines/`（prepare/train/evaluate/report 任务），保留现有 core/models/NGC/runners。

先实现资产 manifest + 显式 Python 工厂 + 固定 F16 assembly；然后做混合后端的端口/时间检查；拿到真实 MATLAB 发动机再实现对应 adapter。不要第一阶段就写任意图编译器、分布式调度器或可视化流程编辑器。

最先落地的验收案例：同一场景和控制器下，仅替换 engine slot 的原生/外部实现，气动、日志、指标与报告代码无需修改；报告清楚记录引擎、通信步长及其数值影响。
