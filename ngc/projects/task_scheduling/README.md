# 工程 04：作业匹配与在线队列

本工程只研究处理节点、作业、容量和时间。目标是看清“预测更准”“单步分配更好”和“整个队列完成得更快”之间的区别。代码集中在一个 `run.py`，没有环境基类、插件或多层策略接口。

零号工程入口：[事件时钟](../../docs/project-zero.md#world) · [学习](../../docs/project-zero.md#learning) · [评测](../../docs/project-zero.md#evaluation) · [记录回放](../../docs/project-zero.md#replay)。

## 一次命令跑完整实验

在 `ngc/` 中：

```bash
uv run --locked --all-extras python projects/task_scheduling/run.py --output artifacts/task_scheduling --seed 11
```

入口实际完成数据采集、回归训练、验证调参、静态匹配、在线事件调度与导出。NumPy 和 SciPy 来自现有依赖，不需要外部服务。默认数值实验通常小于一秒，实际耗时写入 `summary.json`。修改 `--seed` 可重复整套数据划分与评测；不要只提交最好的 seed。

依赖的零号组件主题：数组与批量计算、随机数与可复现性、监督回归、数据划分、事件时钟、指标与结果导出。事件时钟与固定步长动力学各有用途，本例只在到达/完成事件推进，不需要用 World 每毫秒空转。

## 问题、信息和边界

每个节点 `i` 容量为 1，参数为速度 `s_i` 和固定准备时间 `b_i`。作业 `j` 有工作量 `w_j`、到达时刻 `a_j`、截止时间 `d_j`。所有节点兼容所有作业。作业不可拆分，开始后不能抢占；排队时尚未绑定节点。真值处理时间为：

```text
T_ij = w_j / s_i × (1 + 0.15 w_j) + b_i
```

它是教学用归一化时间模型，不代表任何真实机器。调度器可见节点参数和**已到达**作业的信息；不会查询未来作业，不读取上述真值方程来作决策。真实方程只用于模拟完成事件，以及单独标明的离线参考。

静态实验是一次性方阵匹配，大小 `3/5/8/12`；所有作业都要分配，各节点恰好一个作业。在线实验含 `(节点,作业)=(3,5)/(3,35)/(5,45)/(8,60)`，每个规模三条独立到达流，包含队列。静态与在线指标单独报告。

## 三种方法与学习步骤

1. **贪心**：用标称时间 `w/s+b`，每次选择最小代价节点—作业对，移去对应行列。
2. **标称线性分配**：使用同一标称预测，调用 `scipy.optimize.linear_sum_assignment` 优化当前代价矩阵。
3. **学习预测 + 线性分配**：用已完成作业的数据拟合处理时间，再使用相同的线性分配步骤。不是学习器自行满足组合约束，唯一匹配来自求解器。

监督特征为 `[w/s, w²/s, b, 1]`，标签为真实处理时间加标准差 0.025 的测量噪声。使用 1200 个训练样本，工作量 `[1,6]`；独立验证集 400 点，工作量 `[1,8]`；评测工作量 `[3,10]`。节点速度范围 `[0.8,2]`、准备时间 `[0.1,1]`。岭系数 `0/0.01/1` 按验证 MSE 选择。特征显式包含二次项，属于有结构先验的简单模型学习；不宣称自动发现任意处理时间规律。

评测改变工作量范围与规模，特征不含固定节点编号，因此能直接用于未见节点数量。虽然训练区间与测试区间部分重叠，较大工作量是外推；模型形式仍相同，并不等于验证了未知机制的泛化。

## 在线决策与调优

每次有作业到达或节点空闲，取全部空闲节点和已到达未分配作业，代价为：

```text
cost_ij = predicted_T_ij
          + λ max(now + predicted_T_ij - deadline_j, 0)
          - 0.5 (now - arrival_j)
```

第一项偏好短作业，第二项惩罚预计逾期，第三项给等待更久的作业年龄奖励。三种方法看到相同队列并使用同一公式。分配后用真实耗时计算完成时刻，下一事件由未来到达或实际完成决定，预测误差因此会真实影响后续队列。

`λ=0/1/2/4` 在独立的三个 3 节点、18 作业验证流上调优，依据是平均流转时间加平均逾期时间。随后把同一个选定权重用于所有方法和留出任务流。所有候选结果都会保存。默认 seed 11 选到 `λ=0`，这是小验证集上的结果，不表示截止时间对所有场景都不重要。想研究强截止约束，应明确重定义任务目标，再重新划分数据和评测。

这里的线性分配只对**当前一步、当前估计矩阵**最优，在线序列不保证全局最优。各方法均会最终清空有限作业流，所以“完成比例 100%”只是完整性指标；服务质量主要看平均/最大等待、流转时间、逾期比例、平均逾期与资源利用率。

## 如何读默认结果

静态报告还给出知道真值耗时的离线 oracle，下界不能作为拥有同样信息的普通竞争方案。3×3 和 5×5 用枚举所有排列独立核查 oracle；大规模不枚举。默认 seed 11 的静态例子里：

| 规模 | 贪心真值总耗时 | 标称线性分配 | 学习线性分配 |
|---|---:|---:|---:|
| 3 | 51.51 | 46.61 | 46.61 |
| 5 | 94.95 | 79.67 | 79.67 |
| 8 | 131.87 | 115.06 | 115.06 |
| 12 | 130.52 | 101.73 | 101.73 |

学习器时间预测误差显著降低，但分配没有变化：这个模型中工作量的二次变换仍保持工作量排序，完整方阵匹配的排序结构未变。**预测精度提升不必然提升决策指标。** 在线队列的候选作业、截止条件与等待项变化后，两种预测才可能产生不同决策；应读取全部在线结果，不挑一个较好案例作普遍结论。

## 结果和教程站接线

- `summary.json`：参数、训练范围、所有调参结果、选定模型、各场景指标与限制。
- `trajectory.npz`：训练特征/标签/模型；静态真实耗时矩阵、节点与工作量、每种方法的分配对；在线每个场景的 `speed/setup/work/arrival/deadline`，以及各方法的 `node/start/finish`。

在线键名前缀为 `online_{case}_{repeat}`，方法后缀为 `greedy/nominal_assignment/learned_assignment`。例如 `online_1_0_learned_assignment_start` 是对应作业索引的开始时刻。用 `[start,finish]` 和 `node` 可直接画甘特图，用 `arrival` 和 `start` 重建任意时刻队列；无需再实现一份浏览器调度器。全部数组允许 `np.load(..., allow_pickle=False)`。

站点应展示节点—作业连线、甘特图、等待/逾期比较、拟合误差与候选调参记录。本工程目前提供真实 CLI 产物，HTTP 运行入口和页面尚待统一接入；播放已存结果不等于在线重算。

## 练习与后续边界

先改到达强度，观察空闲期与拥塞期；再只改截止时间松紧；最后改预测训练范围。每次保留全部方法的同任务流对照。尝试构造 3×3 手算代价矩阵，理解贪心为什么会把后续节点留在高代价选择中。

当前容量为一，没有异构兼容约束、节点退出、抢占、拆分作业或在线策略学习；学习的是耗时预测器，不是完整动态策略。下一步可先增加一个明确的兼容条件，再考虑事件后的队列重分配；不要为了模板完整而建立通用调度平台。
