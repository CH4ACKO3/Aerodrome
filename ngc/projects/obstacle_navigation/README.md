# 工程 01：有障碍约束的规划、控制与模仿学习

这个首版围绕一个完整任务展开：从起点出发，穿过静态圆形障碍地图，进入目标位置附近并减速。它包含地图生成、全局规划、反馈跟踪、采集示范、真实拟合、验证集调参、留出地图评估与轨迹输出。

**实现边界：目前是二维、可停止的双积分器，不是四旋翼动力学，也不是固定翼模型。** 这里先建立可核查的任务流程，后续再接姿态、推力、升力和转弯约束。固定翼持续前向运动分支尚未实现。这个简化不应出现在教程中被称为“完整飞行器绕障”。

零号工程入口：[运动积分](../../docs/project-zero.md#dynamics) · [坐标单位](../../docs/project-zero.md#coordinates) · [控制](../../docs/project-zero.md#control) · [参考](../../docs/project-zero.md#reference) · [环境事件](../../docs/project-zero.md#environment) · [学习](../../docs/project-zero.md#learning) · [评测](../../docs/project-zero.md#evaluation) · [代码写法](../../docs/project-zero.md#coding-styles)。

## 先看哪些零号工程小节

- 时间、状态与积分：理解控制量的零阶保持和采样周期。
- 坐标与单位：本项目使用平面直角坐标，位置 m、速度 m/s、加速度 m/s²；不是 NED 三维姿态。
- 控制器与参考：区分“生成期望速度”和“用加速度跟踪速度”。
- 环境与事件：障碍膨胀、连续碰撞、到达与超时。
- 数据与学习接口、批量评测：理解示范标签、模型文件和地图留出。
- 代码编写教学：`run.py` 采用函数式组织，按输入→计算→输出阅读；不需要先学习继承或插件系统。

## 一条命令完成整个工程

在 `ngc/` 目录，使用项目已有环境运行：

```bash
uv run --locked --all-extras python projects/obstacle_navigation/run.py \
  --output outputs/obstacle-navigation --seed 0
```

默认任务较小，在 CPU 上采集约千条示范并解一次线性方程，不下载模型、不安装新的学习库。第一次导入绘图库的耗时不属于模型训练耗时。

输出内容：

| 文件 | 可用于什么 |
|---|---|
| `config.json` | 实际参数、seed、训练/验证/测试地图编号、模型版本 |
| `tuning.json` | 验证集上每个速度反馈增益的完整结果 |
| `demonstrations.npz` | 位置误差、专家速度参考、每行所属训练地图 |
| `model.npz` | 径向基中心、宽度、实际拟合权重 |
| `training.json` | 样本量、岭系数、训练误差、实测训练耗时、CPU/NumPy 信息 |
| `trajectories.json` | 全部测试地图、计划路径、真值状态、实际加速度、参考、误差及指标 |
| `summary.json` / `report.md` | 两种方案的到达、碰撞、时间和间距对照 |
| `navigation.png` | 同一批原始数据生成的三张地图和叠加轨迹 |

更改 `--seed` 会整体移动三个数据分区，例如 seed=10 对应训练地图 10–13、验证 110–111、测试 210–212。每次运行应使用不同输出目录保留实验对照；同一目录会覆盖之前的产物。不要只保留最好看的随机种子。

## 模型、观测和终止条件

状态是 `x=(p_x,p_y,v_x,v_y)`，输入是实际加速度 `a`。每个控制周期 `dt=0.1 s` 内输入不变，公共模型 `aerodrome.models.point_mass.step` 使用精确更新：

```text
p_next = p + v dt + 0.5 a dt²
v_next = v + a dt
```

控制器完全观察当前位置、速度以及下一个路径点。两种方案都拥有相同完整静态地图，都使用同一 A* 路径；本版没有传感器噪声、风、局部感知或在线地图更新。

- 地图为 20×14 m；三个圆障碍的中心和半径由地图 seed 决定。
- 运动体半径为 0.25 m。规划再增加 0.65 m 裕度，以容纳跟踪偏差。
- 加速度**向量范数**限制为 2 m/s²，速度参考范数限制为 1.6 m/s。
- 同时满足目标误差 <0.2 m、速度 <0.2 m/s 才算到达；最多运行 100 s。
- 发生碰撞或越界即结束；不会删除失败轨迹或把超时记为成功。

碰撞检查覆盖每两个记录时刻之间的运动：先算端点弦到圆的距离，再减去抛物线偏离弦的上界 `|a| dt²/8`，以及运动体半径。矩形边界也扣除这项。`minimum_clearance_m` 因此是保守连续净间距；略小于真实最小间距，避免仅检查采样点而漏掉穿越。

## 两种方案具体比较什么

共同部分：栅格八邻域 A* 搜索 → 保留障碍裕度的视线简化 → 局部速度参考 → 相同限幅比例速度控制器 → 相同双积分器。

A* 的每条边都检查圆障碍间距，包括对角边。栅格路径只在这个离散图上讨论最短路；视线简化和实际动力学跟踪不构成连续空间最优轨迹。

传统参考用位置差 `e=waypoint-p`：

```text
v_ref = e / max(1, |e| / cruise_speed)
a = norm_limit(velocity_gain * (v_ref - v), acceleration_limit)
```

这让远处参考保持巡航速度，接近路径点时平滑减速；到路点 0.3 m 内切换下一点。

学习方案用训练地图上的传统闭环误差作为输入、传统速度参考作为标签，再增加标准差 0.4 m 的误差扰动并重新计算专家标签。特征为位置差乘距离的高斯径向基，最小二乘加小岭项拟合权重。它确实从示范数据得到参数，运行时不调用专家标签函数。

选择距离特征能保留平面旋转对称性。两方法输出同一层速度参考，使用同一个低层控制器与相同限幅。**学习方法没有学会读取障碍或独立规划；避障路线仍由 A* 提供。** 因此本实验回答的是“局部参考能否被示范模型替代，以及误差如何影响整条轨迹”，不能用于声称模仿学习胜过全局规划。

## 调优顺序与默认记录

1. 先检查 `planned_path` 是否具有所需障碍裕度。
2. 在验证地图上只改变 `velocity_gain=1.6/2.6/3.6`。优先选择成功数最多、其次平均到达时间最短者，若相同则保留先出现者。其他参数保持不变。
3. 固定选出的控制器，用四张训练地图采集示范、拟合一次模型。
4. 使用三张不同测试地图，给两方法相同地图、动作层和控制器。所有样本进入报告。

seed=0 的首轮记录中，三个候选增益均完成两张验证地图；1.6 与 2.6 的平均用时同为 14.8 s，选中 1.6。传统与学习方法各完成 3/3 测试地图，均无碰撞，平均约 14.60/14.63 s。训练参考误差约 0.005 m/s。这是小规模示范结果，学习并没有优于专家；精确数值以运行生成的报告为准。

学习调参可以先改变径向基宽度和训练误差扰动范围，每次只变一个因素；用验证集评估闭环，不用测试结果选择模型。当前 CLI 自动扫描的是传统速度增益，学习参数固定，尚未实现学习超参数搜索、DAgger 或强化学习。

## 复用已训练模型

在 `ngc/` 使用同一 Python 环境运行以下片段，不需要再训练：

```python
import json
import numpy as np
from projects.obstacle_navigation.run import rollout, scene

root = 'outputs/obstacle-navigation'
config = json.load(open(f'{root}/config.json'))['config']
with np.load(f'{root}/model.npz') as archive:
    model = {key: archive[key] for key in archive.files}
result = rollout(scene(200), config, model)
print(result['metrics'])
```

回放时，`state[k]` 对应 `k*dt`，`acceleration[k]` 和 `velocity_reference[k]` 在 `[k*dt,(k+1)*dt)` 内有效。状态条数比动作多一；终止事件来自该轨迹的 `metrics.outcome`。教程站可以直接读取 JSON 绘制地图与曲线，不能另写一套网页动力学。

## 练习和后续接线

先尝试减小规划裕度、提高巡航速度，观察“规划有路但跟踪碰撞”。然后增加一张完全不同布局的地图，保留失败报告，比较训练分布偏移。

后续逐步加入：独立地图集文件、局部观测和重规划、四旋翼姿态/推力约束；最后建立持续前向运动的独立固定翼赛道。两条物理赛道需要各自尺度、转弯约束和终端条件，不能把本例坐标放大后称为固定翼绕障。
