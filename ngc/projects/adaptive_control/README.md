# 工程 05：输入效能变化后的稳定与适应

本工程研究**对象不变、输入通道效能突变**时，固定反馈、理想补偿、在线估计和离线数据估计如何恢复跟踪。它是一维受负载点质量实验；没有实现飞行器失效诊断、卡滞、传感器故障或完全失去控制能力。

零号工程入口：[运动积分](../../docs/project-zero.md#dynamics) · [控制](../../docs/project-zero.md#control) · [观测估计](../../docs/project-zero.md#estimation) · [事件](../../docs/project-zero.md#environment) · [学习](../../docs/project-zero.md#learning) · [评测](../../docs/project-zero.md#evaluation)。

## 一条命令完成整个实验

在 `ngc/` 中运行：

```sh
uv run --locked --all-extras python projects/adaptive_control/run.py --output artifacts/adaptive-control
```

入口自动采集 1200 个训练窗口、保存近邻估计器、运行 24 次评测和单因素调优，再生成 `summary.md`。全部使用 NumPy 与共享点质量模块，不需要 GPU 或训练服务。

依赖零号工程组件主题：状态与精确输入保持积分、反馈/前馈控制、带噪声测量、参数估计、环境事件、数据拟合、批量评价和代码编写方式。`run.py` 使用几个普通函数表达完整流程，无额外类层级。

## 状态、故障与观测的接线位置

系统为 `p_dot=v`，`v_dot=η(t)u−1.2`。位置单位 m，速度 m/s，输入/负载单位 m/s²。共享 `point_mass.step` 对每个保持区间精确积分；控制周期 `0.05 s`，时长 `22 s`。

```text
外生参考 → PD+前馈 → 指令限幅 ±5 → 真实效能 η → 实际输入 → 点质量
                      ↑                                  ↓
                    估计 η ← 指令历史 + 带噪声速度测量 ←───┘
```

故障确实改变输入作用 `ηu`，不是在记录或图形上添加异常。初始 η=1，故障后变为 0.62 或 0.82；另有 η=1 的无故障对照。故障时间分别是 7、10 和 8 秒。真值仅供对象仿真、日志评价和显式标记的 `oracle` 使用。

参考为 `r=0.5sin(0.4t)`，并给所有方法同样的解析速度/加速度。位置观测在首版中无噪声，速度测量有标准差 `0.002 m/s` 的高斯噪声。基础控制计算 `a_des=r_ddot+2(r−p)+2.5(r_dot−v_measured)`，再发出 `u=clip((a_des+1.2)/eta_hat,−5,5)`。

## 四种方法和信息差异

| 方法 | 估计与补偿 | 是否读取真实故障 |
|---|---|---|
| `fixed` | 始终认为 eta_hat=1 | 否 |
| `oracle` | eta_hat=真实 η，立即补偿 | **是；仅为理想参照** |
| `online` | 已完成的24步输入/速度窗口辨识效能 | 否 |
| `learned` | 同一窗口特征进入离线拟合的距离加权近邻回归器 | 否 |

在线法利用 `平均响应=(v[k]−v[k−W])/(W dt)+负载`。若窗口内效能不变，则平均响应等于 `η×平均指令`，由比值可估 η。窗口累积避免逐步速度差分放大噪声；代价是 1.2 秒的数据窗口以及故障窗口混合造成的滞后。估计只使用已经完成的输入区间，不读取新动作造成的未来状态。

该辨识适用于本实验持续抵消正负载的情况，窗口平均输入不接近零。它不是任意激励下的通用辨识器；振荡输入均值为零的场景应改用充分激励和最小二乘统计，不能把本公式直接照搬。在线值截到 `[0.3,1.1]` 是本实验可恢复效能范围的约束。

数据法在效能 `{0.45,0.55,0.75,0.9,1.0}` 上分别采集 240 个窗口，随机指令均值覆盖 `[0.7,4.5]`。每个窗口通过真实共享动力学产生速度响应，输入特征为平均指令和平均响应，标签为采集时已知效能。执行阶段取最近 12 个样本的距离加权标签；存储的样本就是训练模型。没有手写“学习增益”，也没有把真实测试效能传给估计器。

## 划分、调优与评价

训练 seed=21；评测 seed=101/102。0.62 和 0.82 都没有作为训练标签出现；这是**同一种故障类型、未见程度的插值评测**，不是未知故障类型泛化。正常工况是为了检查适应模块是否反而损害原控制器。oracle 的信息更强，不能与其余方法当作同信息比赛。

每次任务保存故障前RMSE、故障后RMSE、5秒后末段RMSE、最大误差、持续恢复时间、末段效能估计误差、饱和比例。恢复要求位置误差进入 ±0.06 m 后保持到实验结束；若未满足，`recovery_s` 为 `null`，不伪造截止时间。完成条件为末段RMSE小于0.06 m。

默认实验通常显示：已知结构的在线辨识比小样本近邻回归更准确；学习估计在无故障情况下也可能制造小偏差。这些结果保留在报告中，不会为了宣称数据方法获胜而隐藏。

调优使用独立工况 η=0.75、故障时间6秒、seed=31，只改变固定控制的 `Kp=1/2/3`，其余增益、噪声与输入限制保持一致。表中同时报告误差与饱和比例。当前没有搜索最优超参数；学生应先看固定控制的增益/稳态误差关系，再研究估计窗口长度与恢复延迟。

10列依次为：时间、真位置、真速度、观测速度、参考位置、控制指令、实际输入、真实效能、估计效能、期望净加速度。实际输入是 `ηu`，净加速度还需要减去负载1.2；图上不要把两者混为一谈。

每行先记录本步当前状态、观测与将执行的指令，再执行一步积分。最后一行对应21.95秒，22秒终态未额外记录。教程站可直接叠加参考/位置、指令/实际输入、真实/估计效能，故障时间来自配置而非浏览器推断。

## 适用边界与扩展任务

首版只说明可恢复的标量效能下降。负载已知，位置理想可见，通道无延迟，参数在故障后保持常数；这些假设是在线法准确的原因之一。更严重效能退化会耗尽限幅内控制裕度，近邻模型也不会可靠外推。

下一步可逐项改变负载误差、效能变化速度、窗口长度或速度噪声，每次只改变一种因素。若增加传感器偏置，需要另建传感器故障通道并重新分析可辨识性；不能继续把所有速度变化都归因于输入效能。
