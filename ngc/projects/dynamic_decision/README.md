# 工程 02：动态参考与有限动作决策

这里有两个**独立数学实验**：2A 跟踪外部信号；2B 在三动作收益矩阵中利用历史信息作决策。没有空间追逐或飞行器任务，不能把两个子问题的指标合并成一个“综合得分”。本目录只有 `run.py` 与说明文档，按函数顺序可从数据生成读到导出。

零号工程入口：[运动积分](../../docs/project-zero.md#dynamics) · [控制](../../docs/project-zero.md#control) · [参考跟踪](../../docs/project-zero.md#reference) · [学习](../../docs/project-zero.md#learning) · [评测](../../docs/project-zero.md#evaluation) · [记录回放](../../docs/project-zero.md#replay)。

## 运行与阅读顺序

在 `ngc/` 内运行：

```bash
uv run --locked --all-extras python projects/dynamic_decision/run.py --output artifacts/dynamic_decision --seed 7
```

会实际采样、训练、验证调参、运行留出场景并写入 `summary.json` 和 `trajectory.npz`，无需下载模型。NumPy 即可执行，默认计算通常不到数秒，实际耗时由 `elapsed_s` 记录。输出目录可自选；同 seed 的数值结果可复现，墙钟耗时不同。

建议先读 `reference → tracking`，再读 `collect_dynamics → run` 中的回归与调参，最后独立阅读 `opponent_actions → fit_transition → play`。每个函数的 docstring 解释其输入、可用信息与目的。依赖的零号组件主题是：时间步与输入保持、RK4 积分、反馈与前馈、数据集划分、最小二乘、批量评测、结果导出。这里的立方阻力在 RK4 各阶段重新计算，不等同于恒加速度质点的精确更新。

## 2A：外生参考跟踪

状态为位置和速度 `x=[p,v]`，输入为标量 `u`：

```text
p_dot = v
v_dot = u - d (0.4 v + 0.18 v³)
|u| <= 6
r(t) = sin(2πft + phase) + 0.25 sin(1.7 × 2πft)
```

全部量采用一致的归一化单位，避免误认为实际机体参数。控制器读取真实 `p,v` 和**当前** `r,r_dot,r_ddot`，无未来参考预览。初态为零，16 秒固定时长，步长 0.02 秒；控制输入每步保持，连续方程用 RK4 积分。参考发生器独立运行，不响应控制行为。

两种方法使用相同的期望加速度：

```text
a_desired = r_ddot + Kp (r-p) + Kd (r_dot-v)
u = clip((a_desired - c1*v - c3*v³) / b, -6, 6)
```

- **标称 PD + 前馈**：使用 `c1=-0.4,c3=0,b=1`，忽略立方阻力。
- **辨识模型 + 同一个 PD**：用监督最小二乘估计 `[c1,c3,b]`，反馈结构、增益、观测及限幅与标称法完全相同。它属于“学习模型，再用普通控制器”，不是神经策略或在线自适应。

台架训练数据为 2000 个速度/输入独立激励点：速度均匀分布于 `[-2.5,2.5]`，输入 `[-6,6]`，加速度标签添加标准差 0.015 的测量噪声。特征为 `[v,v³,u]`，故模型具有明确物理先验；本例不宣称能自动发现任意方程。辨识验证集为 **500** 个点，使用独立 seed。候选岭系数 `0/0.01/1` 按验证 MSE 选择。

增益只在 `f=0.07/0.11` 的验证参考上选择，候选 `(Kp,Kd)` 为 `(2,2)/(4,3)/(6,4)`。以标称控制器平均 RMSE 选出一组，随后给两种方法共同使用；这是固定公共控制器下的模型比较，不代表对每种方法分别调到最佳。评测频率为 `0.17/0.23`，另有 `d=1.2` 的未知参数变化场景。相位也与验证不同。训练、验证、评测角色不会混用。

记录整个时间窗的 RMSE、最大误差、输入 RMS、输入变化率 RMS、饱和比例；包含初始误差瞬态，不截掉难看的前几秒。默认 seed 7 的 RMSE 约为：

| 评测 | 标称模型 | 辨识模型 |
|---|---:|---:|
| f=0.17, d=1 | 0.121 | 0.115 |
| f=0.23, d=1 | 0.149 | 0.138 |
| f=0.23, d=1.2 | 0.156 | 0.141 |

这是一次固定预算实验的结果，不是优越性保证。辨识改善误差也可能提高控制量；必须同时看输入代价。当前没有观测噪声/缺测闭环、在线更新或误差自动恢复机制。

## 2B：有限动作重复博弈

动作是 `0,1,2`，收益矩阵的行表示本方动作、列表示另一方动作：

```text
       0   1   2
  0    0  -1  +1
  1   +1   0  -1
  2   -1  +1   0
```

每轮同时选择动作，结算后才能看到另一方本轮动作。对手序列是独立 Markov 过程：以概率 `p` 沿循环选择下一动作，否则均匀随机选择。非平稳场景在第 300 轮反转循环方向。它不读取本方动作，这使三种方法可面对**完全相同的序列**；这里没有涵盖会针对本方策略作调整的对手。

三种方法为：均匀随机；最近 40 轮的经验频率最优响应；从训练序列学到转移概率后，对上一动作条件下的预测分布作最优响应。所有响应都只读取过去数据；并列动作随机选择。学习器是带伪计数的三分类频率模型，不需要神经网络。

训练库含 `p=0.65/0.75/0.8`，每条 500 轮，共 1500 轮；验证库 `p=0.7`，500 轮，按负对数似然选伪计数 `0.1/1/10`。评测使用未见 `p=0.6/0.9` 及 `p=0.85` 方向切换，每个场景三条独立序列、每条 600 轮。报告列出全部 `场景×重复×方法` 对局，没有只保留最好一条。

默认结果中，转移学习能利用循环相关性；只看动作边缘频率的经验法会损失信息。但转移模型冻结后，方向切换使其后半段收益大幅下降。这是应该保留的失败案例：不能把训练中过去成立的序列规律当成永久规律。报告分别记录前半、后半与全程平均收益；轨迹文件能重建累计收益。未计算“遗憾”，因此也不声称遗憾界或 Nash 收敛。

## 文件如何用于教程站

`summary.json` 保存参数、训练预算、候选调参记录、选定模型和每个场景的评测。`trajectory.npz` 无对象数组，可用 `np.load(..., allow_pickle=False)` 读取：

- `tracking_time_s`：801 个状态时刻；`tracking_{case}_{method}_state` 为 `(801,2)`。
- 同前缀的 `_reference` 为 801 点，`_command` 为 800 个区间输入，画输入时使用 `time[:-1]`。
- `train_features/train_acceleration/model_coefficients`：可重放的拟合数据与模型。
- `game_training_actions/learned_transition`：训练轨迹与学习结果。
- `game_{case}_{repeat}_{method}_{actions,opponent,reward}`：各 600 点，能够按轮回放收益与双方动作。

站点应分成“跟踪曲线”和“动作/收益序列”两个视图，直接读取上述真实结果；改变页面参数后必须重新运行 CLI 才能更新结果。本交付尚未接本地 HTTP runner，不能把播放存档标成实时训练。

## 建议作业与调优顺序

1. 先画参考、位置、输入，观察加大增益和饱和之间的联系；只改一个增益再重跑。
2. 固定控制器，缩小台架训练速度范围，观察评测速度超范围后的模型误差。
3. 单独提高参考频率，再单独改变真实阻力，区分参考泛化和模型参数泛化。
4. 先比较两种历史表示，再加入方向切换；尝试滑动更新条件概率，保留冻结模型作为基线。
5. 最后才增加有噪声观测、在线估计或真正会适应另一方历史的有限状态对手；这些是后续工作，不属于已完成能力。
