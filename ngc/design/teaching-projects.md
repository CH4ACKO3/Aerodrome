# 零号工程与数学问题驱动的实战工程

修订日期：2026-10-08。状态：设计方案，尚未实现新增模型、任务或学习算法。保留“组件示例 + 完整工程”的层级，以数学对象、约束和评价指标组织内容，不预设任务题材。

## 一、工程层级

采用 **一个零号工程 + 五个任务型实战工程**。

- **零号工程**是组件实验室：让读者知道各组件如何输入、计算、输出、组合。原来的速度控制、姿态 PD、串级控制、状态估计、航点跟踪、批量调参，归入其中的小节。
- **实战工程**围绕一个完整任务组织：环境与任务定义 → 可运行的传统基线 → 数据采集与学习方法 → 调优 → 公平比较 → 失败案例分析。
- 一个算法、一张响应曲线或一个网页控件，不再单独算作实战工程。每个实战工程应能作为一个完整的课程大作业，也能作为数值实验模板。

共同写法：每个工程先定义状态、输入、观测、约束、目标与终止条件，再给出传统方法和数据方法的可运行对照。场景由几何体、参考信号、通信图、作业序列和参数变化组成，不再附加园区、巡检或救援故事。

其中工程二使用外生参考信号跟踪与独立的有限动作博弈；工程四使用作业—处理节点调度。模型、动作和目标直接按这些通用问题定义，首版与飞行对象解耦。

### 工程总览

| 编号 | 数学问题 | 完整交付 |
|---|---|---|
| 00 | 组件的输入、状态更新与组合 | 一组短例子和可复用模块 |
| 01 | 状态/输入约束下的运动规划与跟踪 | 双动力学分支、障碍生成、规划控制、学习策略和评测 |
| 02 | 时变参考跟踪与有限动作交互决策 | 两个明确分开的子问题、传统/学习基线、调优与非平稳评测 |
| 03 | 时变节点集合与通信图上的协同控制 | 可变数量、局部观测、队形/覆盖、成员事件与规模泛化 |

| 05 | 执行、观测或模型发生变化后的稳定与适应 | 故障注入、诊断/估计、补偿、残差学习与恢复评测 |

## 四、实战工程一：约束空间中的运动规划与跟踪

### 数学问题与模型

给定离散状态方程 `x[k+1]=f(x[k],u[k],w[k])`、观测 `y[k]=h(x[k])+v[k]`、初始状态、目标状态集合和障碍集合，在状态及输入约束下找到可执行轨迹。完整工程同时包含轨迹生成、反馈跟踪和环境变化后的重规划。

**核心对照：可停止/悬停的系统，与保持前向运动、转弯受限的系统。** 对应已有固定翼方向和待补四旋翼方向；保留二者动力学差异，不赋予外部任务背景。

任务是在给定初态和终点下穿过障碍场，保持飞行动力学可行并抵达目标。终点附近的状态也要检查：旋翼机允许减速悬停，固定翼需要穿过终点窗口并继续可控飞行，不能用“速度降到零”作为固定翼的成功条件。

两条物理赛道分开：

- **旋翼机赛道：** 首版使用约 120×120×40 m 的三维有界空间，包含长方体、圆柱障碍和一条可通行走廊；轨迹经过一个中间状态集合，再到终端悬停集合。默认速度和走廊宽度在新增四旋翼模型完成后确定。
- **固定翼赛道：** 使用几十公里量级的几何空间与大尺度不可进入体积，设置起终端位置、方向和空速。路径必须满足最小转弯半径、爬升和控制范围；复用现有机体时保持其高度/迎角数据范围。不可把旋翼机地图等比例照搬给高速固定翼。

难度依次增加：全图静态场景 → 初始方向不利/窄通路 → 风与观测误差 → 局部地图或移动障碍。首个交付只做全图静态场景。

### 传统方法与数据方法

| 层次 | 首个简单方案 | 后续对照 |
|---|---|---|
| 旋翼机路径规划 | 栅格 A*，再生成可跟踪的平滑参考 | RRT*、局部轨迹优化 |
| 固定翼路径规划 | 考虑位置和航向的可行运动原语搜索 | 带动力学约束的采样规划 |
| 跟踪控制 | 固定的姿态/位置串级控制；固定翼使用空速和航迹外环 | MPC 作为单独对照方法 |
| 学习方法 | 从传统规划与跟踪结果采集数据，行为克隆输出局部运动参考 | DAgger 改善闭环偏离；再考虑 PPO |

学习策略首版输出与传统方法相同的参考层动作，复用相同低层控制器；不把“传统方法控制参考”与“学习方法直接控制电机/舵面”混作一次公平对比。全图和局部观测是两个独立评测设置，不让一个方法看完整障碍图、另一个只看近处距离，却把差异全归因于算法。

### 最小交付、调优与评测

第一里程碑为四旋翼、少量静态障碍、传统规划/跟踪的完整任务；第二里程碑补行为克隆与留出地图；第三里程碑加入固定翼赛道。两类机体最终都要有自己的传统/数据方法对照，不能只保留一个动力学示意。

调优顺序：先验证规划路径可行 → 调跟踪误差 → 查碰撞与到达判据 → 固定这些设置 → 采集示范 → 训练与闭环评估。先解决“规划成功但跟不上”的问题，再调学习奖励或网络。

记录成功率、碰撞率、最小间距、到达误差、时间、路径长度、控制代价、计算时间。检查两个采样点之间的扫掠运动，不能仅检查记录帧是否落入障碍。训练和测试按地图划分；同地图改 seed 不自动算未知地图泛化。

教程站展示障碍、计划轨迹、真实轨迹、局部观测、控制量和失败位置。学生提交一份地图、一套传统方案、一套数据方案和同测试集上的比较报告。

## 五、实战工程二：动态参考与交互决策

本工程有两个子问题：一个研究外生信号随时间变化，另一个研究其他决策者使环境发生变化。它们共用数据记录和评估工具，但不混用状态、动作或成功指标。

### 2A：时变参考信号跟踪

**模型。** 先选一个有界输入的低阶线性系统，再选一个具有局部非线性的通用受控系统。输入参考 `r[k]` 由独立信号发生器给出；参考不会根据控制器行为采取规避动作。误差为 `e[k]=C x[k]-r[k]`，评价误差、输入幅值、输入变化率和约束满足。

**完整实验。** 跟踪正弦组合、平滑分段参考与带有限斜率的阶跃；增加观测噪声和短时缺测，比较完全观测与仅有测量的情形。训练/测试按参考频率范围、切换方式和模型参数划分，不只换噪声 seed。

**方法。** 从 PID/状态反馈开始，加入参考前馈或预测控制作为后续传统对照。数据方法先用基线轨迹做行为克隆，再比较学习局部模型、由相同控制器使用该模型的方式。不同方法面对同样的参考预览长度，不能一个看未来整条信号、另一个只能看当前值。

**调优。** 先调标称系统稳定性，再改变参考变化速度，然后加入观测误差；固定这些实验条件之后训练学习方法。首版只开放少数增益和模型参数。

**交付。** 一个参考生成器、一套传统控制、一套数据方法、未知参考族评估和失败回放。指标为时域误差、相位滞后、控制代价、饱和比例与计算耗时，关注整个时间区间内的跟踪表现。

### 2B：有限动作的重复博弈

**模型。** 使用小型收益矩阵定义双方有限动作与收益。首个例子采用三动作循环收益，随后扩展为少量可观测模式切换的收益矩阵；可用动作仅表示收益矩阵中的数学选项。先做完全可观测，再隐藏对手当前模式。

**完整实验。** 对手先使用固定混合策略，再周期性切换策略，最后使用根据历史选择动作的有限状态策略。实验需要覆盖固定策略、非平稳策略、未见策略及不同历史观测长度，不能只训练一个对手并报告一次得分。

**方法。** 均匀随机是最低基线；传统方法采用经验频率响应或在线遗憾学习。数据方法先拟合对手动作分布，再使用学习到的历史表示作决策。规模确实需要时再比较策略梯度；小型问题先使用表格方法，不以大网络作为起点。

**调优与评价。** 固定对手库和评测步数，比较平均收益、随时间变化的累计收益、对手切换后的恢复，以及完整交叉对局矩阵。混合策略应通过动作分布评价，不能要求每一步都是唯一的“正确动作”。若需要计算遗憾，明确其参照策略和可用信息。

**交付。** 有限动作环境、规则对手、传统在线方法、一个学习方法和可重放的动作日志。教程站展示参考信号曲线和收益/动作序列两个独立视图，不用三维飞行动画包装收益矩阵。

## 六、实战工程三：可变规模系统的编队与协同

### 数学问题与“不确定数量”的含义

**主题：队伍在变，局部规则或共享策略能否继续工作？**

令有效节点集合为 `V[k]`，通信图为 `G[k]=(V[k],E[k])`；节点具有局部状态、输入以及邻居观测。任务是收敛到参考队形、通过几何约束区域、形成区域覆盖并重新集合。首版用低阶运动模型验证交互规则，再在旋翼机上检查可执行性；固定翼扩展采用持续运动队形与对应空间尺度。

分别研究三个问题，避免只把 batch 数改大就声称完成：

1. **每次任务的数量不同：** 例如训练使用 2/4/6 架，测试 3/5/8 架。
2. **任务过程中成员变化：** 预定时刻有成员加入、退出或暂时失联。
3. **单个体不知道全局数量：** 只接收通信范围内的邻机信息，不直接拿到所有飞机的真值列表。

### 对比方案

传统方法分两组：带明确领机的相对位置保持，以及不依赖单一领机的邻居一致性/虚拟结构跟踪。区域覆盖先采用固定区域划分，再增加简单的分布式任务协商。

数据方法从参数共享策略开始，用邻居集合的汇总表示替代“把固定 N 个体拼成固定长输入”。后续引入图结构编码或 MAPPO：训练时是否使用集中信息、执行时能看到什么，必须单独标注。数量泛化、排列顺序变化和暂时缺少邻机是不同测试维度。

### 最小实现与调优

首版只做 2–6 架旋翼机集合与编队通过宽走廊，比较两个传统方法；再训练一个共享的模仿策略。随后补未见数量、窄走廊变队形、成员退出和区域覆盖，最后再做强化学习对照。

JAX 需要固定计算形状，可在一个任务配置中设置有限容量和有效成员 mask。无效槽位不参与邻居聚合、控制、奖励和指标；有效数量在容量内变化。这个上限是实现边界，不能宣称支持任意规模。现有 World 不自动具备这层行为，需要新增任务级处理。

先调单机跟踪，再调邻居作用范围和队形收敛，随后引入通信延迟和数量变化。所有方法面对相同的成员事件和通信条件。

评测任务完成率、队形误差、最小机间距、碰撞、成员变化后的恢复时间、区域覆盖率和通信量。总分按有效个体数/有效时长归一化，同时保留全队是否完成任务，避免数量增加带来虚假的高分。

教程站支持调整有效数量、点击加入/退出事件、查看邻接图和单机观测，所有事件进入可重放日志。

## 七、实战工程四：容量约束下的匹配与调度

### 数学问题与模型

给定处理节点集合、作业集合、兼容关系与完成耗时；每个节点具有容量和可用时刻，每个作业具有工作量、到达时刻和截止时间。决策是在何时把哪个作业交给哪个可用节点，评价总完成耗时、等待与逾期情况。所有实体仅使用索引、时间和容量，首版代价由等待和处理时间构成。

首版假设作业不可拆分，处理一旦开始就不中断；排队中的作业可以重分配。先做一次性一对一匹配，再做带队列的多轮调度，最后增加作业到达与处理节点退出。静态匹配和动态调度分开评分，不能拿只解决一步的算法和完整动态策略直接混评。

最小实例从 3 个节点、5 个作业开始，使结果可手工核查；随后扩大规模并改变工作量分布。新作业是否预先可知是一个明确的实验条件，不能只给优化方法完整未来信息。

### 传统与数据方案

- 静态最小版本：最短预计完成时间贪心，与线性分配方法比较；小规模结果可用枚举独立校核。
- 动态版本：滚动重分配、截止时间规则，以及小规模优化求解作为参考。只在目标和约束确实匹配时使用同一个求解器。
- 学习版本：先用静态优化解训练任务评分器，再由共同的匹配步骤生成完整分配；动态策略学习作为后续扩展。

共同匹配步骤造成的约束满足必须归功于该步骤，不能宣称网络独立学会了所有组合约束。后续如开放抢占或任务拆分，应作为另一组环境规则单独比较。

### 完整调优与评测

第一里程碑是静态分配、三个手算小例子和规模稍大的自动场景；第二里程碑增加监督学习和未见规模；第三里程碑加入任务动态变化。

分别调时间代价、重分配频率与学习器，不同时改变场景生成和评分函数。对照使用相同任务流，比较完成比例、平均/最大等待、截止时间违约、资源利用率、重分配次数和计算耗时。优化器超时要记录，近似结果不写成全局最优。

教程站显示节点—作业连线、队列和甘特图、未分配作业及每次决策代价。学生提交场景、传统方法、数据方法及同任务流上的对照结果。

## 八、实战工程五：故障后的稳定与适应控制

### 数学问题与模型

采用 `x[k+1]=f(x[k],u_actual[k],θ[k])` 和 `y[k]=h(x[k])+b[k]+v[k]`：故障可改变输入通道、对象参数 `θ` 或观测偏置 `b`。这些变化分别建模，不混成一个未说明来源的随机扰动。

**主题：系统结构或参数发生变化后，固定反馈、在线估计和适应补偿各自能恢复什么？**

旋翼机完成悬停/缓慢位置跟踪，固定翼完成平飞/缓转弯。在一次任务中注入已记录的故障，比较不适应的基线与能估计、调整或重构的方案。

首批故障分别施加，不直接堆叠：

| 故障类别 | 模拟方式 | 应观察的现象 |
|---|---|---|
| 执行效能下降 | 实际输出是指令的一个减小比例 | 跟踪误差、剩余控制裕度 |
| 执行器偏置/卡滞 | 加偏置或保持某个实际舵量/推力 | 非对称响应、持续输入饱和 |
| 执行延迟增加 | 改变指令到实际输出的动态 | 振荡、相位滞后、恢复时间 |
| 传感器偏置/短时缺测 | 修改观测，不改机体真值 | 估计偏差、误诊、闭环恶化 |
| 参数变化 | 质量/惯量或局部气动参数改变 | 标称模型和真实对象不一致 |

故障插在明确的物理或测量位置：控制器指令 → 实际执行输出 → 机体 → 传感器 → 估计器。不能仅往画图记录里加异常。除单独标明的理想诊断对照外，控制器不直接读取故障种类和注入时间。

### 三层方法对照

1. **固定基线：** 原控制器不变，量化性能损失。
2. **传统适应：** 从最简单的执行效能在线估计与增益调整开始，再比较有明确物理意义的控制分配/重构；检测滞后和估计误差必须进入实验。
3. **数据方法：** 先学一个局部模型残差或效能估计器，仍由同一控制器执行；在有稳定传统基线和数据覆盖后，再加入残差策略对照。

故障恢复策略先只在可恢复的小范围退化上研究。完整失去一个旋翼/关键舵面不保证还能完成原任务；不能以增大增益强行掩盖不可控状态。此时任务目标应明确改为减小姿态发散、受控下降或其它模型实际能够支持的降级结果。

### 最小实现、调优与评测

先实现旋翼机单通道轻度效能下降和固定翼单舵面效能下降，对比固定控制与已知效能的理想补偿；再加入在线估计，把“估计得准”和“控制恢复好”分开评价；最后才引入未知故障和学习方法。

数据划分同时考虑故障发生时间、程度和类型。只在同一种故障程度上改变噪声，不构成对未知故障的泛化。调优先确定故障前稳定性，再处理检测/估计速度，最后调整补偿速度与控制限幅。

指标包括故障前性能、最大姿态偏差、恢复时间、剩余跟踪误差、控制饱和比例、误报/漏报和降级任务结果。每一批评估必须包含无故障案例，检查适应机制是否在正常情况下反而损害控制。

教程站叠加故障时间线、实际执行输出、估计效能、机体响应和控制指令。读者应能看出故障发生、被观察到、被补偿的三个不同时刻。

## 九、每个实战工程统一交付什么

每个工程都包含以下内容，而非只交一个训练脚本：

1. **任务说明：** 什么叫完成，什么叫失败；动力学、传感器、可用信息和计算预算。
2. **可运行环境：** 默认场景、少量有解释力的变体、可保存的 seed 与事件序列。
3. **传统基线：** 默认参数、局限、调参步骤；先跑通，再采集训练数据。
4. **数据方法：** 数据产生方式、输入/输出、训练/验证划分、最小训练入口与一个可重放模型。
5. **调优记录：** 起始结果、只改变的因素、变化后的结果及失败案例，不只是最终最佳曲线。
6. **公平评测：** 同观测、同动作层、同场景和预算；不同信息条件另开赛道。多个种子、统计分布与失败数同时报告。
7. **教程页：** 任务总览、运行引导、方法比较、交互回放、作业扩展和全部产物下载。

数据方法没有超过传统基线，也是有效教学结果；不得删除失败样本、只选最好的训练种子，或用训练奖励替代任务成功率。

首版训练算力不做未经测量的承诺。先把小环境和短实验在 CPU 跑通，公布训练步数、墙钟时间和设备；长训练用独立 CLI 执行，教程站主要负责短评估、结果导入和回放。

## 十、与教程站和框架的结合

### 内容组织

建议采用“工程总览 → 零号工程 → 实战工程 → 每个工程的小节”的结构。教材七章保持理论主线，各章链接到相应工程步骤；工程页反向链接所需组件。本文只记录拟议结构，不直接重写尚未确定的章节正文或导航。

零号工程以公式、单组件曲线和短实验为主；实战工程以任务地图、时间线、多方案叠加、评测表和失败回放为主。网页不承担另一套物理实现。

### 运行方式

沿用已有静态教程/本地 JAX 服务：在线展示由真实程序产生的参考结果；本地修改参数后重算。参数已改变但尚未运行时，明确保留旧结果的标签。训练、评估和回放分开：播放已存轨迹不能称为正在实时训练或实时仿真。

F-16 配平要求 float64，应在本地服务启动时启用 JAX x64，各实验显式选 dtype，不在任务线程内来回改全局精度。多实验分发先用小型 ID→runner 映射；无需新增通用插件平台。

### 代码组织

通用模型与算法仍放在 `ngc/src/aerodrome/` 的现有模块。任务项目可使用一个实际目录，如 `ngc/projects/obstacle_navigation/`，放场景、任务定义、基线、数据生成、训练与评估入口；小项目允许合并脚本，不按空模板机械建文件。

零号组件例子继续沿用 `ngc/examples/`。只有任务真正落地时才创建对应工程目录。已有 Gym 适配用于学习环境接线，不能因此复制动力学或训练器。

结果保存实际参数、模型/算法版本、场景和 seed、状态/观测/动作、事件、任务指标。训练项目额外记录数据划分、训练预算和模型文件。3D 与地图从同一结果投影，指标从原始数值记录计算。

## 十一、实施顺序

**阶段 A：补零号的关键组件，并交付工程一的第一条完整任务。**

优先补四旋翼模型/悬停、外环控制、障碍查询与任务评估；同时保留已有固定翼验证基线。先做四旋翼静态绕障的传统方案，再补简单模仿学习和固定翼赛道。

**阶段 B：交付工程三和工程五的最小版本。**

复用已验证单机控制，完成可变数量的基础编队、一次成员变化，以及轻度效能退化后的恢复对照。两者都先有可解释传统基线，再加入学习方法。

**阶段 C：并行安排独立的抽象任务。**

工程二的参考跟踪/有限动作博弈和工程四的作业调度不等待高保真飞行模型，可先完成小型、可独立核查的完整比较，再接教程站。

**阶段 D：形成统一的工程评测与教程站入口。**

补地图/工况留出集、对照报告、预计算展示和本地运行。每个工程成熟一部分就接入一部分，不等待五个工程全部完成。

测试沿用项目约定：真实入口的端到端场景和模型/算法的模块行为对照；数值部分用解析性质、独立参考或收敛检查。不要为参数拒绝、私有结构和每一条条件分支重新扩张测试。
