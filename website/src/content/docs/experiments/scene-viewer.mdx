物理模型决定飞机怎么运动，渲染模型决定你看到什么。这里用同一个刚体 World 轨迹，
切换局部三维场景、地球尺度视图和航迹地图。默认视图使用内置资源，地理数据可按需配置。

## 各个库负责什么

| 组件 | 当前接入能力 | 数据要求 |
| --- | --- | --- |
| Three.js + GLTFLoader | 飞机 GLB、姿态、舵面、轨迹回放、可控相机 | Scene/Frame v1 与资产映射 |
| Three.js Sky / Water | 参数化天空、海面与反射 | 内置生成法线纹理，无外部贴图 |
| 3d-tiles-renderer | 城市/地形 3D Tiles 流式加载，LOD 与缓存上限 | tileset URL；局部 Y-up 或 ECEF，真实数据需 origin_lla |
| CesiumJS | 地球椭球、ECEF 飞机姿态、3D Tiles、地形服务 | 本地原点；地形/瓦片地址可选 |
| MapLibre GL JS | 地图、位置与航向、样式和 DEM 地形 | 样式 URL、raster-dem TileJSON 可选 |

城市、山地、海洋、高空是**显示环境预设**：前三者用程序地形、示意楼房和海面组织画面，高空预设调整天空散射。飞机的轨迹高度、重力、空气密度、碰撞与传感器数据由仿真模型决定。
需要真实地形或城市时，可配置 DEM 或 3D Tiles 数据；Cesium/MapLibre 则使用各自的地理视图设置。

## 从本地仿真到画面

在[速度控制实验](/Aerodrome/experiments/velocity-control/)运行并下载结果 JSON，再导入这里。
结果文件包含 Scene/Frame v1 记录的姿态。回放时，浏览器用位置插值和四元数 SLERP 连接相邻记录，呈现已经计算好的轨迹。
离线 FPS 记录浏览器的绘图调用频率，可用于观察回放流畅度；仿真的时间进度由结果文件中的时间戳确定。

Three.js 适配器还提供 `submit(RenderRequest)`，应用相机和命名关节，并返回 v1 receipt；
`presented` 表示浏览器已提交绘制。跨进程 WebSocket 运输计划通过后续适配器连接。

## 战斗机模型工作流

内置模型是可下载的[简化战斗机 GLB](/Aerodrome/models/training-fighter.glb)，用于展示姿态、舵面和航迹。
推荐在 Blender 制作并导出 glTF 2.0 / GLB：以米为单位，拆分 `elevator`、`rudder`、
`aileron_left`、`aileron_right`，把原点放在实际铰链处，保留 rest pose。
浏览器通过这些命名节点控制舵面的绝对偏角。其他动画可在资产制作时单独设计，并在接入相应控制接口后使用。

资产 URI 与物理模型 ID 独立。你可以用同一个外观显示不同飞行动力学模型，也能替换外观而不修改 World。
模型轴向通过 `body_from_asset_quaternion` 描述，最终旋转严格为 `A R_nb R_body_asset`；
真实地理场景则使用 WGS84 原点构造 NED 到 ECEF 变换。

## 外部资源

各后端按需加载，切换时释放旧 WebGL 上下文、模型与控制器；Three.js 像素比上限为 1.5，
3D Tiles 使用几何误差与有界缓存控制开销。外部资源由浏览器直接访问，连接参数在对应后端中配置。

参考官方接口：[Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)、
[3D Tiles Renderer](https://github.com/NASA-AMMOS/3DTilesRendererJS)、
[CesiumJS](https://cesium.com/learn/cesiumjs-learn/cesiumjs-quickstart/)、
[MapLibre](https://maplibre.org/maplibre-gl-js/docs/)。
